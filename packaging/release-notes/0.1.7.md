Plico 0.1.7 fixes the AppImage start-up on X11, makes update checks clearer
and stabilises compressed saves.

## Fixes

- **AppImage on X11**: on recent distributions (Arch, Fedora 45) Plico
  crashed at start-up with a segmentation fault in X11 sessions. The
  `.AppImage` bundled the libxkbcommon-x11 of Ubuntu 22.04, which does not get
  along with the system's newer libxkbcommon; it now uses the system's,
  together with the libxcb extensions. Wayland was not affected. The `.deb`
  lists them as dependencies.
- **Updates**: when GitHub refuses the check because its rate limit has been
  reached (60 requests per hour per IP address), Plico says so and tells when
  to try again, instead of a generic "GitHub answered 403".
- **Save Compressed**: a file with nothing to gain could, once in a while, be
  written anyway with "Saved: 10 B (0%)". The size comparison was thrown off
  by the random identifier every save gave the PDF; compression now keeps the
  document's own, and the same content always gives the same size.

## Packages

- **AppImage** (`Plico-0.1.7-x86_64.AppImage`), **Debian and Ubuntu**
  (`plico_0.1.7_amd64.deb`), **Flatpak** (`Plico-0.1.7-x86_64.flatpak`) and
  **Arch Linux** (`plico` in the AUR), as in 0.1.6.
- **Verification**: `SHA256SUMS` and, for every file, a GitHub provenance
  attestation: `gh attestation verify <file> -R gradia64/Plico`.
